Aviva — Setup & Usage Instructions
Ask your sales and marketing data anything.
Aviva is a natural language analytics assistant. Type a question in plain English, and Aviva routes it to the right data source, generates SQL, runs it against your database, and returns a clean answer.

Project Structure
aviva/
├── app.py              # Streamlit frontend — run this to launch the UI
├── pipeline.py         # Core query pipeline (routing → SQL → answer)
├── indexer.py          # Builds FAISS semantic search index
├── loader.py           # Loads CSV files into SQLite database
├── config.py           # Paths, API key, and data source routing table

First-Time Setup
1. Clone the repo and create a virtual environment
bashcd aviva
python -m venv venv
source venv/bin/activate        # Mac/Linux
# venv\Scripts\activate         # Windows
2. Install dependencies
bashpip install -r requirements.txt
3. Add your Anthropic API key
Create a .env file in the project root:
ANTHROPIC_API_KEY=sk-ant-your-key-here
Get your key from console.anthropic.com.
4. Load data into SQLite
bashpython loader.py
Expected output:
Loaded 'sales_data' — 20 rows, 10 columns
Loaded 'marketing_data' — 20 rows, 9 columns
All sources loaded into /your/path/aviva/data/sales.db
5. Build the FAISS index
bashpython indexer.py
This embeds your data source descriptions using all-MiniLM-L6-v2 and saves the index. Run this any time you add or update a data source in config.py.
6. Launch Aviva
bashstreamlit run app.py
Opens at http://localhost:8501.

How to Use
Type any question about your data in the input box and hit Enter.
Sales questions (routes to sales_data):

"Who is the top performing sales rep?"
"What were total sales in the West region?"
"Which product category had the highest revenue?"
"Show me all orders from Acme Corp"

Marketing questions (routes to marketing_data):

"Which channel had the best ROI?"
"What was our email campaign revenue?"
"Which campaign spent the most on Google Ads?"
"How many conversions did we get from Facebook?"

Use the View SQL Query expander to see the exact query Aviva generated.

Adding a New Data Source

Drop your CSV file into the data/ folder.
Open config.py and add an entry to CSV_SOURCES:

python"your_source_name": {
    "path": os.path.join(DATA_DIR, "your_file.csv"),
    "description": (
        "Brief description of what this data contains. "
        "Use this source for questions about X, Y, and Z. "
        "Does not contain [anything that might cause routing confusion]."
    ),
}
The description is what Aviva uses for semantic routing — be specific about when to use this source and when not to.

Re-run the loader and indexer:

bashpython loader.py
python indexer.py
No other changes needed. Aviva routes automatically.

Architecture
User question
     ↓
indexer.search_index()        ← FAISS semantic search across source descriptions
     ↓
Correct table identified
     ↓
PRAGMA table_info()           ← Fetch schema (column names + types)
     ↓
Claude generates SQL          ← Question + schema → SQL query
     ↓
SQLite executes query         ← Raw results returned
     ↓
Claude formats answer         ← Results → natural language response
     ↓
Answer displayed in UI
The routing layer is the core differentiator. FAISS finds the semantically closest data source description to the user's question before any SQL is generated — preventing retrieval contamination across sources.

Known Limitations

Date sensitivity: The sample data covers Jan–Apr 2024. Questions like "this month" will return no results since the data is historical.
Single-row guardrail: Charts only appear for multi-row results.
TF-IDF replaced: Routing uses real sentence embeddings (all-MiniLM-L6-v2), not keyword matching.
No authentication: Aviva is a local dev tool. Do not expose to the internet without adding auth.
